# Flux, Argo CD and KEDA

Scaling a Deployment to 0 is easy; keeping it at 0 is the hard part. A GitOps tool syncs the replica count from Git back into the cluster, and an autoscaler scales the workload up when its trigger fires. KubeSiesta pauses these while a namespace sleeps and resumes them when it wakes.

Pick the section that matches how your workloads are deployed. Use either Flux or Argo CD, not both, for a given namespace. KEDA can be combined with any of them.

## Plain manifests (no GitOps)

Workloads applied with `kubectl apply`, Kustomize, Helm from a CI pipeline, and so on. Leave Flux and Argo CD disabled.

Nothing reverts a scale-down by itself. But **re-applying a namespace's manifests while it sleeps brings its replicas back**, for example a CI deploy on Saturday. Either skip deploys to sleeping namespaces, or wake the namespace in the UI first. If it happens anyway, the next scheduler run during off hours puts the namespace back to sleep (it is running without a lease).

## Flux

Enable with `flux.enabled: true` (chart) / `SIESTA_FLUX_ENABLED=true`.

**What you need to do:** label each Flux `Kustomization` with the namespace it deploys:

```yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: apps-dev1
  namespace: flux-system
  labels:
    kube-siesta.io/namespace: dev1   # <prefix>/namespace: <namespace it deploys>
spec:
  interval: 10m
  sourceRef:
    kind: GitRepository
    name: flux-system
  path: ./apps/dev1
  prune: true
```

**On sleep** the app sets `spec.suspend: true` on every Kustomization labelled for the namespace (in `SIESTA_FLUX_NAMESPACE`) and on every HelmRelease inside the namespace. **On wake** it unsuspends the ones it suspended, HelmReleases first, and asks Flux to reconcile now.

**Isolation.** A Kustomization that deploys several namespaces can't be suspended for just one of them; while it runs, it would put the replicas back. So by default (`requireIsolation: true`) sleeping a namespace is refused unless at least one Kustomization is labelled for it, and the UI shows **not isolated** for such namespaces. Split shared Kustomizations into one per namespace. Several Kustomizations per namespace are fine; all are suspended.

Turning `requireIsolation` off lets the app sleep such namespaces anyway, but Flux will scale them back up on its next reconcile.

## Argo CD

Enable with `argocd.enabled: true` (chart) / `SIESTA_ARGOCD_ENABLED=true`.

**What you need to do:** label each `Application` with the namespace it deploys. Applications can live in any namespace (Argo CD's "apps in any namespace" works).

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: dev1
  namespace: argocd
  labels:
    kube-siesta.io/namespace: dev1   # <prefix>/namespace: <namespace it deploys>
spec:
  destination:
    namespace: dev1
  syncPolicy:
    automated: {prune: true, selfHeal: true}
  # project, source, ...
```

**On sleep** the app saves the Application's `spec.syncPolicy.automated` in a `<prefix>/auto-sync` annotation and removes it, so Argo CD stops syncing (the app shows as OutOfSync, which is expected). **On wake** it puts the saved policy back exactly and asks Argo CD to refresh. Applications that were already on manual sync are left alone.

**Isolation** works as for Flux: by default sleeping is refused unless an Application is labelled for the namespace.

### ApplicationSets and app of apps

If your Applications are generated by an **ApplicationSet** or managed by a parent **app of apps**, the parent puts `syncPolicy.automated` straight back. The UI then shows **re-enabled** in the Argo CD column. Tell the parent to leave the sync policy alone:

- **ApplicationSet** (Argo CD 2.9+):

  ```yaml
  spec:
    ignoreApplicationDifferences:
      - jsonPointers: [/spec/syncPolicy]
    template:
      metadata:
        labels:
          kube-siesta.io/namespace: '{{.path.basename}}'   # label generated per app
  ```

- **App of apps**: in the parent Application,

  ```yaml
  spec:
    ignoreDifferences:
      - group: argoproj.io
        kind: Application
        jsonPointers: [/spec/syncPolicy]
    syncPolicy:
      syncOptions: [RespectIgnoreDifferences=true]
  ```

If the policy was put back anyway, the app turns it off again the next time it pauses the namespace, and on wake it restores the policy it saved first.

## KEDA

Enable with `keda.enabled: true` (chart) / `SIESTA_KEDA_ENABLED=true`.

KEDA scales workloads from external triggers (queue length, cron, metrics). Without this, a ScaledObject would scale a sleeping Deployment straight back up.

**On sleep** the app pauses every ScaledObject and ScaledJob in the namespace (the `autoscaling.keda.sh/paused: "true"` annotation). **On wake** it removes the pause from the ones it paused. Objects someone else paused stay paused. Jobs a ScaledJob already started are not stopped.

No labels are needed; KEDA objects are found by namespace.

## What the UI shows

With these enabled, the namespace table gets a column for each:

| Column | Values |
|---|---|
| Flux | **not isolated** (no labelled Kustomization), *suspended*, *active* |
| Argo CD | **not isolated** (no labelled Application), **re-enabled** (a parent turned auto-sync back on), *auto-sync off*, *auto-sync* |
| KEDA | *—* (no KEDA objects), *paused*, *active* |
